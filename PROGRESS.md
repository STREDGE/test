## Проект
- **Цель клиента:** в Grand Mobile 62.51 (Android, Unity IL2CPP, x64, **OFFLINE**,
  open-world режим) сделать так, чтобы **пули попадали во врагов НЕЗАВИСИМО от
  того, куда целится игрок**.
- **Клиент хочет:** НЕ aimbot (камера остаётся на месте), а чтобы любой выстрел
  примерно в сторону NPC — засчитывался как попадание.
- **Стек:** чистый Lua для GameGuardian. Никакого Frida/инжекта.
- **Античит:** клиентский, кодовое имя **Grand Bot** (только локальный, серверной
  валидации нет — игра офлайн).

## Принятое решение по методу
**Комбо A + B** (из обсуждения):
- **A. Collider inflation** — раздуть `CapsuleCollider.radius` у ближайших NPC
  (капсула-«бочка» вокруг каждого). Радиус капсулы, высоту не трогать (иначе
  проваливаются в геометрию).
- **B. One-shot damage** — `WeaponDamage` игрока = 9999. Любое касание
  раздутой капсулы = килл одной пулей.
- **C (bullet magnet)** — отклонена: GG Lua не успевает за быстрыми пулями
  автомата, работает только на снарядах.

## Почему НЕ silent aim
В чистом GG Lua **невозможен** — требует hook функции `Weapon.Fire()` /
`Physics.Raycast()`, GG функции не хукает. Клиенту это объяснено, он согласился
на A+B.

## Правила из CLAUDE.md, которые уже всплыли и действуют
- Правило №12: **никогда не целить в origin кости**. При bullet-magnet / аиме —
  только через head-offset `+1.6..1.75` по Y от origin.
- Правило №11: стек Lua → только таблицы и углы, без векторной математики.
- Игра OFFLINE → серверных рисков нет, но Grand Bot ведёт поведенческую
  статистику локально. Нужна **рандомизация** магнита и **дистанционный
  фильтр 150 м** (не раздувать всех NPC на карте).

## СЛЕДУЮЩИЙ ШАГ (когда клиент пришлёт дамп)
1. Распарсить `03_anchors.txt`:
   - Найти адреса строк `CapsuleCollider`, `NPCManager`, `WeaponDamage`,
     `Faction`, `Civilian`, `Cop`.
   - По каждому адресу — вычислить offset от базы `libil2cpp.so`
     (из `01_ranges.txt`) → это position в `.rodata`.
2. Для каждой строки-якоря — дать клиенту **уточнитель №2**:
   - `gg.searchPointer(addr)` → находим `Il2CppClass*`, указывающий на
     эту строку (поле name в структуре класса).
   - Из `Il2CppClass` по типовым arm64-оффсетам (`fields` ≈ `+0x80`,
     `methods` ≈ `+0x98`, `field_count` ≈ `+0x118`) читаем массив полей.
   - Для `CapsuleCollider`: нужны оффсеты `m_Radius` и `m_Height`.
   - Для `NPCManager`: массив `activeNPCs` (указатель + count).
   - Для `Faction`: enum-значения civilian/cop/enemy.
3. Параллельно клиент выполняет ручные найти-фильтр-изменить:
   - HP игрока: получи урон — отфильтруй по `refineNumber`.
   - WeaponDamage: стреляй — ищи float, который падает к боеприпасам.
4. Собрать финальный **A+B скрипт** с меню:
   - `[1] Включить магнит коллайдеров (радиус N м, дистанция ≤150 м)`
   - `[2] Выключить магнит`
   - `[3] One-shot damage на моё оружие`
   - `[4] Сброс damage`
   - `[5] Фильтр: мирных не трогать (по faction enum)`
   - `[6] Выход`
   - Рандомизация: инфлейтить 60–80% NPC в радиусе, не все; радиус
     ±0.5 м рандом; интервал обновления 250–400 мс.

## Критичные оффсеты, которые ещё нужны
- `libil2cpp.so` base runtime → из `01_ranges.txt`.
- `global-metadata.dat` base → из `02_metadata.txt` (magic найден или нет).
- `CapsuleCollider.m_Radius` inner offset в компоненте → типично `0x40`
  или `0x50` в Unity 2020–2022 arm64, подтвердить по дампу.
- `CapsuleCollider.m_Height` → обычно `m_Radius + 4`.
- `Player.m_Weapon` → указатель.
- `Weapon.damage` → float.
- `NPCManager.activeNPCs` или аналог → List<NPC>.
